## What Worked

- **Refrens item-creation automation** (reuse for future items): user logs into Refrens themselves in the in-app browser (`mcp__Claude_Browser__*`); Claude never handles credentials. Business URL key: `happiness-in-a-bowl-ltd`. Add Item form direct URL: `https://refrens.com/app/happiness-in-a-bowl-ltd/inventory/new`. Per item, run ONE `javascript_tool` call that: waits for `input[placeholder="Enter name of your item"]`; sets name; sets SKU (find via the `SKU ID` label → nearest input; the auto-value is numeric); checks "This item can be sold to customers" (REQUIRED so it appears on invoices — checkbox found by row text `can be sold to customers`); clicks the collapsed `2. Pricing & Taxation` header; waits ~500ms; sets Selling Price = `document.querySelectorAll('input[type="number"]')[1]` (index 0=Buying, 1=Selling); then clicks `Save & Add Item`. Use a React-safe setter (native value setter + dispatch `input`+`change`). A successful save NAVIGATES away, which surfaces as a `javascript_tool` "Promise was collected" error — that means SUCCESS. Gate the save on validation (`sku set && parseFloat(selling)===parseFloat(price) && sold checked`). Currency defaults to MUR already; unit left blank (not needed for matching); item type Product.
- To read/verify the catalog: Inventory → All Items → click Reset on filters (default filter `Manage Stock: Yes` HIDES the new items, which have stock mgmt off) → Download As → Download CSV → Download (saves to `C:\Users\User\Downloads\items.csv`, overwrites). Cross-check names case-insensitively.
- **Alias + fuzzy-suggestion pattern** for menu-name normalization: exact match → alias lookup → token/bigram fuzzy suggestion, always human-confirmed, worked well for reconciling inconsistent client order names against the canonical menu.
- **Refrens auto-adder userscript** (`refrens-adder.user.js`, root; app-side "Copy items for Refrens adder" + install UI in `RefrensCatalogPanel`): a Tampermonkey userscript that walk-away-creates the missing catalog items. Reads a `HIBQ:`-prefixed queue from the clipboard, drives the Add-Item form (name, SKU, "sold to customers", selling price), clicks Save, and self-continues across the SPA navigation via a `hib_refrens_queue` localStorage queue + `@match .../inventory*` re-fire. Control panel with Start/Pause/Load-from-clipboard/Clear + progress + error log + circuit breaker (pause after 3 consecutive errors). Proven end-to-end 2026-09-02. Item form URL, business key `happiness-in-a-bowl-ltd`, "Promise was collected = success" note all still apply.
- **Refrens React gotchas learned building the userscript (do NOT re-derive):**
  - The Pricing & Taxation section is collapsed via a `height:0; overflow:hidden` ancestor (`collapser-panel-item-body`), NOT `display:none` — so `offsetParent`/`getBoundingClientRect().height` on the fields are FALSE POSITIVES for "visible". Detect collapse by walking the input's ancestors for one with `offsetHeight === 0`. Clicking the header `span` leaf expands it.
  - Among the form's `input[type="number"]`, index 0 = Buying Price, index 1 = Selling Price (confirmed against the save payload).
  - Typing the NAME makes Refrens auto-generate the SKU (alphanumeric slug), so set SKU LAST, right before Save; find the SKU input positionally (the text input right after the name input), not by numeric value.
  - **Refrens' React form will NOT commit a programmatically-set Selling Price by any DOM method** (native value setter, execCommand typing, repeated typing with settle delays all leave `sellingPrice=undefined` in the outgoing save request). SOLUTION: intercept the page's OWN `POST https://api.refrens.com/businesses/happiness-in-a-bowl-ltd/inventories` (the request the Save button itself sends — same session/JWT, NOT the paid Refrens API) and inject the correct `sellingPrice` into its JSON body in-flight, matching the queued item by `name`. This is free and reliable; do not attempt to fix the price via the form again.

## What Didn't Work / Gotchas

- **PowerShell quirk:** every command echoes a harmless `cd : Cannot find path ...\Happiness_in_a_Bowl\Happiness_in_a_Bowl` error because the shell is already in the project dir — ignore it, the real command still runs.
- **Commit messages:** PowerShell here-strings + inline `;` chaining mangle `-m`; write the message to a temp file and use `git commit -F` instead.
- **Git push auth:** the remote is stored without a token; push using the user-env token `HIAB_GIT` inline and scrub it from output:
  ```
  $t=[System.Environment]::GetEnvironmentVariable('HIAB_GIT','User'); git push "https://$t@github.com/kennymourat9613/Happiness_in_a_Bowl.git" main 2>&1 | ForEach-Object { $_ -replace [regex]::Escape($t),'***' }
  ```
- In-app browser downloads DO land in `C:\Users\User\Downloads` (briefly as a `*.tmp`, then finalized, e.g. `items.csv`).
- Refrens allows duplicate item names (no dedup on create) — always cross-check the catalog before creating to avoid adding more duplicates.
- Never enter user credentials; the user logs into Refrens themselves.
- Refrens bulk item import and the API are both paid (Premium) features, which blocked those approaches while on the free plan — hence the browser-automation workaround.
